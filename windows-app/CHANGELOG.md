# AIClockBridge (Windows) 更新记录

Windows 桥接的版本线**独立于固件**。固件版本见 `firmware/include/config.h` 的
`FW_VERSION`；两者从 0.5.0 起分开走，因为桥接侧的改动大多不碰设备，设备协议也没变。

版本号写在 `AIClockBridge/AIClockBridge.csproj` 的 `<Version>`，
`build-release.ps1` 读它来命名 `dist\AIClockBridge-<版本>-Windows-x64\`。

## 0.5.17

- **启动时自动升级 Claude 状态 hook 脚本。** 以前只有点右键「启用 Claude 桌面状态同步」才会重写 `%APPDATA%\AIClockBridge\claude-status-hook.ps1`，升级桥接后旧脚本会一直沿用（11-02 发现 10-30 的脚本仍缺 `idle_prompt`）。现在启动时，若脚本存在、内容与本版不同、且 `settings.json` 仍注册着它，就静默重写，日志记 `[hooks]`。不新建脚本，不改 `settings.json`，也不生成备份；写入失败下次启动再试。
- 5 项新离线检查（仅用临时文件）。

## 0.5.4

### 修复

- **429 退避闸门按 provider 拆开。** 之前两家共用一对 `_nextAllowedFetch` /
  `_nextScheduledFetch`，所以 chatgpt.com 的一个 429（Retry-After 可以是几小时）
  会把 Claude 的 OAuth 请求一起关在门外。Claude 于是掉到桌面缓存**并卡在那儿**：
  重新登录没用，托盘的「刷新」也没用——`userInitiated` 只跳过轮询节奏，跳不过硬闸门，
  而这个闸门跟凭据根本无关。这就是"切到客户端缓存后再刷新凭据也回不去"的原因。
  顺带给 Retry-After 加了 15 分钟上限，免得一个离谱的响应头把某一家停播一整天。

- **Claude 的 429 之前是看不见的。** 退避读的是 `ChooseClaude()` 选出来的读数，
  而接口一失败那就是桌面缓存对象，`RateLimited` 恒为 false。现在退避读原始响应。

- **回退到桌面缓存不再是静音的。** 日志里 `[usage] claude:` 一行都没有过，正是因为
  落盘的是缓存对象、它的 `Error` 是 null。现在接口的失败原因一定会进日志，也会跟在
  托盘那行的 `（桌面缓存 · …）` 后面，能直接看出是限流、凭据过期还是代理超时。

- 缓存读数也能当"上一次好数据"了。`Merge()` 原先要求 `!old.DesktopCache`，
  于是"接口失败 → 用缓存"之后再遇上"缓存文件也读不到"，额度会直接清空；
  现在保留旧数字并带上 `DesktopCache` 标记，由 `DesktopStale` 正常过期。

## 0.5.3

### 变更

- **Claude 额度改为优先走 OAuth 接口，桌面版缓存降级为兜底。** 原先是缓存无条件优先，
  只有读不到缓存才走网络。反过来的理由有两条，第二条是硬伤：

  1. 接口是**实时**的，缓存最多滞后 15 分钟（桌面版每 15.00 分钟才写一条样本）
  2. **只有接口带重置倒计时**。`plan-usage-history.json` 里只有 `fh`/`sd` 两个百分比，
     没有任何重置时间——所以走缓存时设备上根本显示不出"几小时后重置"

  取舍规则收敛在一个纯函数 `ChooseClaude()` 里：

  | 情况 | 结果 |
  |---|---|
  | 网络轮次，接口有数 | **用接口** |
  | 网络轮次，接口失败但有缓存 | 用缓存（旧的真数字胜过错误信息） |
  | 网络轮次，接口失败且无缓存 | 用接口的错误（好歹说明原因） |
  | 非网络轮次，接口刚成功过 | **不动**——否则每分钟会把实时数据降级成旧缓存样本 |
  | 非网络轮次，接口已沉默 | 用缓存 |

  「刚成功过」的窗口是 `ApiTrustWindow` = 2 × 网络轮询间隔 = 240 秒，必须大于一个
  网络周期，否则中间那些每 60 秒的本地轮次会把实时读数覆盖掉。有测试钉住这个不变式。

  请求频率没变：接口仍是 120 秒一次，受同一个 429 退避闸门管。

- **托盘会标明额度来自哪一边**：`（凭据实时 · HH:mm）` 还是
  `（桌面缓存 · MM-dd HH:mm）`。两个源质量不同（后者没有重置倒计时），
  不标出来又会变成"看不出当前是哪条路"。

- 没有凭据时的文案从「未找到桌面额度缓存或 CLI 凭据」改成
  「未找到 CLI/插件凭据…，回退到桌面版缓存」——桌面缓存现在是独立判断的，
  旧文案会误导成两边都没了。

## 0.5.2

### 新增

- **股票中文名可以走 USB 串口了**，不再强制依赖 WiFi。设备字库是纯 ASCII，中文名一直是
  桥接渲染成 RGB565 位图条、由设备走 HTTP `GET /stock/names.raw` 拉取——而那条路需要
  设备连上 WiFi 并配好 bridgeHost。于是**纯 USB 的设备只显示代码，中文名永远不出来，
  界面上没有任何地方说得出原因**。

  现在多了一条串口通道，语义和 HTTP 版一致（设备主动要，而不是桥接硬塞）：

  ```
  设备 -> 桥接:  #WANTNAMES <rev>
  桥接 -> 设备:  #NAMES <rev> <count>
                 #NAMEROW <rev> <strip> <row> <base64>   ← 每帧一个像素行
  ```

  **一帧一个像素行**是关键：156×2 = 312 字节、base64 后 416 字符、加前缀约 432 字节，
  稳稳落在固件 `serialLine[1600]` 里；设备直接解码进 HTTP 路径本来就在用的那个 312 字节
  `rowBuf`，不需要 15KB 缓冲（这颗芯片也拿不出来）。312 能被 3 整除，base64 永不补位。

  按 250ms 节拍每次发 2 行限流（约 3.6KB/s，线速 11.5KB/s，设备 UART 缓冲 2048 字节且
  每个 `loop()` 才排空一次）。一整套约 6 秒，且只在自选股变化时传一次。设备不在股票页时
  一个字节都不发，收到的行也会被丢弃——那些行是直接 blit 到屏幕的，画到别的页面上会糊。

- 托盘设备行下方新增网络状态：`WiFi <SSID> <IP> · 桥接 <host>`，未连时给出提示。
  设备每次 `#DEVICE` 回包本来就带 `ip`/`ssid`/`bridge`，只是从没显示过——中文名不出来
  这个问题因此完全不可见。串口连上时也会记进日志。

### 修复

- 股票中文名条的渲染失败不再被报成「行情请求失败」。渲染是 GDI 活不是网络活，之前它被
  包在网络请求的 `try` 里，出错会栽赃给网络并计入 HttpClient 重建计数；而它的表现恰好
  就是「价格在更新、中文名不出来」。

## 0.5.1

修一个实测确认的故障：**Codex 额度和股票行情会同时卡死不动，重启程序才恢复**。

### 修复

- **HttpClient 现在能自愈，不必重启程序**。`static readonly HttpClient` 会把系统代理
  在进程启动那一刻固化下来（`HttpClient.DefaultProxy` 全进程只解析一次），
  连接池的 `PooledConnectionLifetime` 又默认无限。于是**代理客户端（v2rayN 之类）
  在桥接运行期间开关系统代理，桥接就会一直往一个已经不在监听的代理发请求**，
  直到进程重启为止。卡住的正好是唯二需要公网的两项——Codex 额度和股票行情；
  Claude 额度（读本地文件）和网速（读本地计数器）毫发无伤，所以看起来像"通讯卡了"。

  现在连续 3 次**传输层**失败（拿不到任何响应：DNS、连接、TLS、超时）就重建
  HttpClient 并重新读一遍 WinINET 代理设置，两次重建之间至少间隔 30 秒。
  HTTP 401/429 不算——那说明链路是通的，重建纯属瞎折腾。

- **股票拉取加了防重入**。5 秒定时器配 5 秒超时，代理一慢就会叠加并发请求，
  而且旧响应可能后到并把新价格覆盖回去。

- **限流退避不再厚此薄彼**。`_nextAllowedFetch` 是两个 provider 共用的闸门，
  退避却只看 `claude.RateLimited`——Claude 一旦 429，Codex 跟着饿 300 秒；
  而 Codex 自己 429 则完全不退避。现在任一方 429 都会推迟闸门。

### 新增

- **文件日志**：`%APPDATA%\AIClockBridge\logs\bridge.log`（超过 1MB 滚动一代）。
  程序是 `WinExe`，没有控制台，**此前所有 `Console.Error.WriteLine` 都被写进无效句柄
  然后丢弃**——串口连断、端口绑定失败、额度请求出错，全都没有任何痕迹。
  这正是上面那个故障排查困难的原因：卡住的额度和"数字恰好没变"看起来一模一样。
  另外会记录未捕获异常（`UnhandledException` / `ThreadException` / 未观察的 Task 异常），
  托盘崩溃不再只是图标悄悄消失。托盘菜单新增「打开日志文件夹」。

- **股票失败会显示出来了**。此前是纯 `catch {}`，保留旧价格且不留痕迹。
  现在托盘会显示「股票：行情请求失败：…，最后成功 HH:mm」。
  （Codex 额度本来就有这个提示，`（缓存：…）`，正是靠它定位到本次问题的。）

## 0.5.0

版本线与固件分离的起点。对应固件 0.4.13（协议未变，任意较新固件都能配）。

### 新增

- **开机自动启动**（托盘菜单开关）。写 `HKCU\...\CurrentVersion\Run`，用户级、
  不需要管理员权限。状态以注册表为准，不在 `settings.json` 存副本；任务管理器
  「启动应用」里的禁用（`StartupApproved\Run` 标志位）会被正确识别，勾选框不会
  和系统显示打架。升级换了版本目录后启动时自愈，把 Run 项改指当前 exe。
  开启时若检测到旧文档教的启动文件夹快捷方式，会询问后删除，避免启动两次。
- **单实例**。重复启动提示后退出，不再出现两个托盘图标争抢 8765 端口和 CH340 串口。
  开机自启那份带 `--autostart`，重复启动时静默退出、不弹框。

### 修复

- **HTTP 服务绑定失败会重试**（5 秒后起，每 15 秒一次，成功即停）。此前登录瞬间
  网络栈未就绪导致绑定失败时只打一行日志，局域网桥接会一直不可用到手动重启程序。
- **Claude 桌面版额度不再每 15 分钟闪一次「已过期」**。实测桌面版每 15.00 分钟整点
  写一条样本，而过期阈值恰好也是 15 分钟，最新样本会在下一条写入的同一瞬间被判过期，
  设备额度周期性变成 `-`。阈值改为 35 分钟（跨两个采样周期，并给桌面版每约 4 小时
  自更新重启留出余量）。
- **桌面版缓存路径不再写死 MSIX publisher hash**。改为枚举
  `%LOCALAPPDATA%\Packages\*Claude*\LocalCache\Roaming\Claude\`。此前写死
  `Claude_pzs8sxrjxfjjc`，而那串是签名证书主体算出来的，证书轮换或改包名会让路径
  静默失效——额度永远显示 `-`，日志里没有任何线索。

### 变更

- **桌面版额度改为每 60 秒重读一次**（原 120 秒），打开托盘菜单和点「刷新」也一定重读。
  桌面缓存是本地文件，读取零成本；走网络的额度接口（Codex、无桌面版时的 Claude OAuth）
  仍保持 120 秒，请求频率未变。注意显示滞后的大头是桌面版自己的 15 分钟采样节拍，
  不是这个间隔。
- 发布产物改为**框架依赖的单文件 exe**（约 27MB，需 .NET 8 Desktop Runtime），
  由 `build-release.ps1` 一条命令产出到 `dist\`，并清理旧产物目录。
  `setup-dev-env.ps1` 可一次性装好用户级 .NET 8 SDK。
